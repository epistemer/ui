# ADR 0010: tables take generated columns, keep their state in the URL, and answer in one response

| | |
|---|---|
| Status | Accepted |
| Date | 2026-11-22 |
| Roadmap item | D7.1 |
| Deciders | epistemer decided the columns (S2, S3) and the transport (S4) in the brainstorm of 2026-11-22; Claude proposed the rest |

## Context

visual-design §2.4 says server state becomes a Go type read from the
request, as forms works. models already expects it: `listing.Source` is
"a table implements it with its own state". Three questions were open.

**Row to cells.** In the record of zp
([server-state-design.md](../server-state-design.md) §1) a column's name
was written four times and joined by strings, and cell values were
flattened to text and parsed again.

**State.** Sort was a button's name and not part of the form, so paging
lost it. A filter value that didn't parse was dropped silently.

**Transport.** Rows came over SSE from the same URL. The inventory listed
that under what zp got right. Read closely, it cost a script dependency
for any rows at all, a second request per view, a held connection,
mismatched ids between the page and the stream with a script to patch
them, an error event nothing showed, and history caching switched off;
and the count ran before the first row, so nothing slow was deferred.

## Options

Row to cells:

1. Typed columns declared by hand, each with an accessor.
2. **Column sets generated by models** from each `_view` relation: name,
   label, a kind from the SQL type, enum options and a getter.
3. A row template that fills a slot per column.

A generated column's value:

a. The Go type sqlc wrote, as a second type parameter. The generator
   would repeat sqlc's type mapping, and ui would receive the driver's
   null types, which it can't import.
b. **A plain value with a kind**, nulls unwrapped by the generated getter.
c. `any` from one method per row type. A surprise type shows only when a
   page renders.

Transport:

i. **One response.** A GET form and links; htmx swaps the table's region.
ii. SSE, as the record.
iii. HTML streamed in the one response. An error after the first flush
   can't change the status, and models' listing returns a slice.

## Decision

2 with b, and i.

- **Columns.** models generates them; a table picks from them and sets
  what may be searched, sorted and filtered. What SQL can't know (an
  image, an amount, a link to another record, a hidden column) is said on
  the table. Option 1 remains possible, since a column can be built by
  hand.
- **State.** `ui/tables` declares a table once and binds a state per
  request from the query string: search, filters, sort, page and size,
  all of them. The state is the `listing.Source`.
- **Filters are a `forms.Form`** bound with `forms.FromValues`. A value
  that doesn't parse is an error on its field, and the table shows no
  rows until it is fixed.
- **Transport.** One handler and one response, with rows inline. It works
  without script; htmx swaps the region and moves the address bar. No SSE
  for rows. The inventory's "keep: rows streamed over SSE" is withdrawn:
  the goal was a fast first paint, and a page of 20 to 100 rows in one
  response has it.
- **Bulk selection** is a second form joined to the row checkboxes by the
  `form` attribute, and each bulk action is one of its submit buttons
  with a `formaction`.

## Consequences

- No column name is typed in an app. A view's column that is renamed
  breaks the build where a table names it.
- ui/tables waits for a models release with the column type (its v0.4.0).
  The slice spike declares the proposed shapes locally first.
- Filters are limited to what `listing` can express: equality and ranges.
  Several values, "is empty" and "contains" each need a models amendment.
- A table on a link column's filter waits for the remote select (D8).
- ADR 0005's sentence that htmx does "streamed rows" no longer describes
  a table; a live table is a later need with its own design.
- There is one table component. The record's second, client-side table
  has no successor.
- The selection is the page's; "all rows that match" is not in the first
  cut (S15).
